# UI/UX audit: Ledgerly static fixture (landing, invoices, signup)

**Scope:** `index.html` (marketing landing), `invoices.html` (app screen: invoice detail + month metrics + sent list + recurring), `signup.html` (account creation), `styles.css` (shared, 125 lines). Platform: plain static HTML + one CSS file, no framework, no JS beyond inline `onclick`, no tokens/variables.
**Evidence:** code read in full (all four files). Rendered UI NOT seen: the one permitted browser attempt failed on the `file://` URL. Contrast ratios below were computed with the WCAG formula from the hex values in `styles.css`, not measured in a browser.
**Assumed top user tasks:** 1) Understand what Ledgerly is and start a free account. 2) Find an invoice and act on it (send a reminder, mark as paid, download). 3) See what is owed/overdue at a glance.

Paths below are relative to the fixture folder; `css` = `styles.css`.

## Verdict

The product's actual value (send invoices, track overdue, get paid) is good and plainly written, but it is buried at the bottom of the landing page under a jargon hero, five equal-weight buttons, a forced "which one are you?" choice and eight shouting promos. Across all three pages nothing is primary: every button is a solid saturated color, the biggest and loudest control in the app is Delete, and "Clear form" is a twin of "Submit". Several essentials fail basic accessibility: the signup entry point and the search button are unfocusable `<span onclick>` elements, ten of eleven signup fields have no label, and the fee disclosure, hero copy, empty state and "Mark as paid" button sit between 1.7:1 and 2.6:1 contrast. The biggest strength is the raw material: a sensible system font stack, real invoice data with useful columns, and three feature bullets that already say what the product does.

## Top fixes (do these first)

1. **Make one action primary per screen and demote the dangerous ones.** Landing: a single solid "Create your free account" button in the hero; others become links or go. Invoice: "Send reminder" solid, "Mark as paid" and "Download PDF" outline, Duplicate/Delete as quiet links (red only in a confirm step). Signup: remove "Clear form" and "Cancel my subscription", rename Submit to "Create account". Why: today users cannot tell where to start, and the easiest things to hit are Delete and a button that wipes 11 fields. Effort: S.
2. **Make the entry points real controls.** Replace `span.ghostlink` with an `<a href="signup.html">` button, replace `span.go` with a `<button>Search</button>`, remove the underline/link styling from the static "Send invoices in seconds" heading. Why: the main conversion path is invisible (black text) and unreachable by keyboard. Effort: S.
3. **Fix the failing contrasts.** Hero paragraph and motto, footer (it carries the 3.5% fee), `.btn-grey`, `.empty`, green/orange buttons, orange promo text, sidebar links; also raise body weight from 300 to 400. Why: essential text is unreadable for many users and the fee disclosure reads as hidden. Effort: S.
4. **Rebuild the signup form around what a free account needs.** Name, email, password only; real `<label for>` on each; `type="email"`; drop DOB, address, occupation, household income and card number (or move billing to the moment of upgrade and accept spaces/dashes); per-field error text shown only on error; constrain the form to about 400px. Why: this is the conversion step and it currently drains all goodwill. Effort: M.
5. **Use plain words and consistent names, and show where you are.** Launchpad/The Vault/Hive/Pulse/Toolbox become Home/Invoices/Clients/Reports/Settings (or whatever they really are); page `<title>`, visible page heading and nav label all say "Invoices"; link "Join" and page heading agree ("Sign up"); active nav gets two distinctions (color + weight or accent border); sidebar marks "Sent"; move the brand top-left and link it home; trim utilities to Help + Log in. Why: fails the trunk test on every page. Effort: S.
6. **Cut the landing page to its point.** Replace "Welcome to Ledgerly!" / "Work. Smarter." / the synergy paragraph with the existing feature headline and bullets; delete the About section, the chooser, and all but one or two promos; state the 3.5% fee near pricing. Why: answers the five first-screen questions using content that already exists; mostly deletion. Effort: S.
7. **Introduce a small token set and snap to it.** CSS custom properties for a spacing scale, a px type scale (kill nested `em`), about 9 greys, primary/semantic shades, one radius, a 2 to 3 step shadow scale lit from above; then replace most `1px solid #999` borders with spacing/background. Why: the root cause of the "undesigned" look; 14 font sizes, 10 ad-hoc greys, 16 spacing values. Effort: M.

## System health

Distinct **font sizes:** 14 declared (px: 11, 12, 13, 14, 15, 16, 17, 18, 21, 22, 46; em: 1em, 2.5em, 0.875em), 15 effective because `.help .tiny` nests 0.875em inside 0.875em (about 11.5px). · **weights:** 2 (300, 700), but the base is 300, below the 400 floor. · **colors:** 22 distinct values (20 hex + 2 rgba) and zero tokens; 10 of them are unrelated neutral greys (`#555 #4d4d4d #999 #9a9a9a #9b9b9b #aaa #bbb #c9c9c9 #e8e8e8 #eee`), including three that differ by one step (`#999/#9a9a9a/#9b9b9b`). Five saturated hues (two blues `#1a6fe0`/`#2456c9`, green, orange, red) with no shades. · **spacing values:** 16 distinct px values (3, 4, 6, 7, 8, 9, 10, 12, 13, 14, 16, 18, 20, 22, 26, 30) plus 2 em values; one-offs like 7/9/13/22 show there is no scale. · **shadows:** 2, both ad hoc and with opposing light directions. · **radii:** 3 (0, 4px, 18px) mixed within one button family. · **border widths:** 2 (1px used 16 times, 2px once); 14 of the 1px borders are the same `#999`, two are `#aaa`.

**Exists:** a good system font stack (`css:5`), `box-sizing` reset, a shared `.btn` base, a single stylesheet.
**Missing:** every token system: spacing scale, type scale, grey ramp, primary/semantic shades, elevation scale, radius, focus style, breakpoints.
**Consolidate:** define CSS custom properties in `:root` of `styles.css` (extend this file; no new dependency): about 8 spacing steps (4, 8, 12, 16, 24, 32, 48, 64), 6 to 7 font sizes in px/rem (12, 14, 16, 18, 24, 30, 40), weights 400/600, 9 greys of one temperature, primary 100 to 900, red/green/amber with at least 100/500/700, one radius (4 or 6px), shadows sm/md/lg lit from above. Then map each one-off to its nearest token.

## What's working

- The three feature bullets and their headline (`index.html:82-87`) state real, concrete benefits in plain language. This is the landing page; promote it, do not rewrite it.
- "Create your free account" is the right call to action wording; it just needs to be a real, visible button.
- System font stack, `lang="en"`, charset and viewport meta on every page.
- App content is real and useful: sensible columns, ISO dates that sort, status values that map to the sidebar filters, metrics that match the third user task.

# B3 gap review: Refactoring UI, PDF pages 171 to 252

Chapters: Creating Depth, Working with Images, Finishing Touches, Leveling Up.
Reference files compared: `visual-design.md` (VD), `design-tokens.md` (DT), `audit-checklist.md` (AC).
All 77 page images that exist in the range were viewed (no files for 197, 198, 218, 247, 248; pages 185, 193, 207, 223, 227, 233, 237 are blank; 171, 199, 219, 249 are chapter title cards). Ambiguous captions on p177, p186, p189, p216 were re-read from 3x crops.

Values given with a CSS property are read from the book's captions. Sizes prefixed "about" (accent bar thicknesses, etc.) are estimated from the illustrations, which carry no caption for them.

Caption convention: the book prints colors in a shortened form such as `hsla(0,0%,.2)` (lightness argument omitted). Below they are written in valid CSS as `hsla(0,0%,0%,.2)`.

## 1. Missing or under-specified

Ordered by how much they change what gets built.

1. **Raised-element recipe has no values (p175-176).** The book's raised button is two layered shadows: a 1px top highlight `inset 0 1px 0 hsl(224,84%,74%)` (an opaque, hand-picked lighter tint of the button's own blue, used instead of translucent white because white drains saturation) plus a cast shadow `0 1px 3px hsla(0,0%,0%,.2)`. The shadow has a positive y offset so it only shows beneath the element, and the blur stays at a couple of px so the edge is crisp. The profile diagrams also give the reasoning for which edge to show: the viewer looks slightly down at the screen, so a raised object reveals its top edge and hides its bottom edge. Where: VD section 6 first bullet, and a new `--raised-highlight` / `--raised` pair in DT under elevation (the highlight color has to be picked per button color: same hue, noticeably lighter).

2. **Inset/well recipe has no values (p177-178).** Bottom lip: `0 -2px 0 hsla(0,0%,100%,.15)` (caption prints it without the `inset` keyword, but the body text and the picture show an inset shadow with negative y, so use `inset 0 -2px 0 hsla(0,0%,100%,.15)` or a bottom border). Top occlusion: `inset 0 2px 2px hsla(0,0%,0%,.1)`, positive y so it does not leak out at the bottom. Shown on a dark panel applied to a file-drop well, a text input and a checkbox; the well is also filled darker than its surrounding panel. Note the lip here is translucent white, so VD's "hand-picked color, not translucent white" should be scoped to the raised top highlight only. Where: VD section 6, DT new `--inset-well` token.

3. **Text-over-image techniques have no numbers (p203-206).** Overlay: `background-color: hsla(0,0%,0%,.55)` over the photo. Overlay color is chosen by text color: dark overlay for light text, light overlay for dark text (p204; VD only says "semi-transparent overlay"). Lower-contrast variant: brightness +40%, contrast -70%, with dark text on the resulting pale image. Colorize: fill `#035581` in multiply mode over a contrast-reduced, desaturated photo; side benefit is that the photo takes on the brand color. Glow: `text-shadow: 0 0 50px hsla(0,0%,0%,.4)` (zero x/y offset, 50px blur); still lower image contrast a little, just less than you would without the glow. The failure illustration (p203) shows the actual test: neither white nor dark text survives because the same headline crosses both bright and dark regions. Where: VD section 7 second bullet; optionally DT `--image-overlay`, `--text-glow`.

4. **User-image edge treatment has no value, and the bad pattern is not described (p215-217).** Fix: `box-shadow: inset 0 0 0 1px hsla(0,0%,0%,.1)` (zero blur, 1px spread: acts as a translucent inner border, which the book offers for people who dislike the recessed look of a blurred inner shadow). Rejected pattern: a solid opaque ring, `border: 2px solid hsl(212,12%,72%)`, because it clashes with image colors. Cropping illustration: image as `background-size: cover`, centered in a fixed-size box, overflow cropped equally on both sides; the before-picture is a card grid whose rows go ragged because each photo keeps its own aspect ratio. Where: VD section 7 last bullet; DT `--image-inner-edge`.

5. **Elevation scale usage, anchored by the book's own examples (p181-184).** Button: `0 1px 3px hsla(0,0%,0%,.2)` (level 1). User-menu dropdown: `0 4px 6px hsla(0,0%,0%,.1)` (level 2 geometry, at half the alpha). Modal: `0 15px 35px hsla(0,0%,0%,.2)` (level 5). Dialog used in the borders chapter: `0 5px 15px 0 hsla(0,0%,0%,.15)` (level 3 geometry, p239). Method for building the scale: fix the smallest and largest first, then fill in between with roughly linear steps (p183). In every before-picture the dropdown/modal has only a 1px border and looks flat on the page, which is the thing to look for in an audit. Where: DT "Elevation scale" paragraph; VD section 6.

6. **Interaction shadows, concrete (p183-184).** Button default `0 4px 6px hsla(0,0%,0%,.2)`, on press `0 1px 3px hsla(0,0%,0%,.2)`; the pressed state also uses a slightly darker fill. Draggable list row: on grab the row gets a white raised background plus a shadow, a drag handle appears at its left, and it extends slightly wider than its siblings. Where: VD section 6 "Shadows respond to interaction".

7. **Flat solid shadow value and color choice (p192).** `box-shadow: 0 3px 0 hsl(220,7%,83%)`: zero blur, 3px offset, and an opaque grey slightly darker than the page background rather than translucent black. Shown on cart rows (cards). Also p191: a login card lighter than the page with inputs slightly darker than the card (inset) and a footer strip darker than the page sitting beneath the card (further away). Where: VD section 6 "Flat designs" bullet; DT optional `--shadow-flat`.

8. **Overlap values (p194-196).** Search card straddling hero and next section: `margin-bottom: -60px`. Card taller than its colored band: `margin: -60px 0 -60px 0`. Carousel prev/next buttons: circular, centered on the card's left and right edges via `margin-left/right: -24px` (half their width). Overlapping avatars / avatar over a cover photo: `border: 4px solid #FFFFFF` (i.e. the surface color), so there is always a gap. Where: VD section 6 "Overlap" bullet.

9. **Two-part shadow anatomy (p186-188, p252).** The book's demo card uses `0 4px 6px hsla(0,0%,0%,.7), 0 5px 15px hsla(0,0%,0%,.1)` on p186, repeated on p252. That `.7` is five times darker than anything in the p189 scale and looks like a misprint (possibly `.07`); do not adopt it, use the p189 scale already in DT. What is worth adding to VD: the point of splitting is control, so the big shadow can stay faint while the tight one keeps the element's edge defined (p187-188 show each shadow in isolation and combined).

10. **"Fewer borders" values and one condition (p238-241).** (a) A shadow can replace the outer border of a panel, but only when the panel's fill differs from the page background (p239). (b) Header/search/footer strips separated by fill alone: `background-color: hsl(200,10%,94%)` against white, borders removed (p240). If a region already has its own fill and a border, the border is the redundant one. (c) List rows: row dividers dropped, `margin-bottom: 6px` between rows, and the selected-row highlight becomes an inset rounded rectangle instead of a full-bleed band (p241). Where: VD section 8 "Fewer borders".

11. **Empty-state anatomy (p235-236).** Simple version: centered illustration, one line saying what to do (phrased as an action, not as "nothing found"), one solid primary button. Full-page version: the normal page chrome (page title, top-right create button, tabs, filter, search box) is removed entirely and replaced by a headline, one supporting sentence, one primary button, and a large low-contrast illustration bleeding off the right edge. The bad version also shows the create action twice (toolbar and body); the good one has it once. Where: VD section 8 "Design empty states".

12. **Component anatomies in "Think outside the box" (p243-246).** VD lists the ideas; the pictures give the structure.
    - Dropdown: wide panel with a pointer caret to its trigger; primary items in a two-column grid, each = colored outline icon + bold title + one-line muted description, optional small "NEW" pill; secondary links in a second section distinguished by a tinted background (not a divider), laid out one per row with the description inline to the right.
    - Table: merge non-sortable columns into stacked cells (name over role, amount over policy type), secondary line smaller and lighter; column count drops from six to four; avatar added to the first cell; status as a pill with dark text on a light tint of the same hue (green approved, yellow pending). Condition: only merge columns that do not need to be sortable.
    - Radio group to cards: equal-width cards in a row, each = small uppercase letter-spaced label, large value with its unit smaller, price beneath; selected card = colored border + faint tint of that color + check badge top-right; unselected = white card with a small shadow.
    Where: VD section 8 last bullet, or a short "patterns" subsection.

13. **Accent border placement details (p224-226).** Card: about 4px band across the top edge only, clipped by the card radius. Nav: about 2px bar under the active item only, as wide as the label, sitting on the nav's bottom edge, paired with a color/weight change on the label. Alert: about 3 to 4px bar on the left edge of a tinted panel, colored with a darker shade of the same hue. Headline: short bar (a few dozen px, far narrower than the headline), left-aligned, between headline and body. Page: full-width band across the very top of the viewport. Where: VD section 8 "Accent borders".

14. **Supercharge-defaults specifics (p220-222).** Bullets: filled circular check icons in the brand color, or a topic-specific icon (padlock in a muted circular chip for security features). Quotes: opening and closing marks enlarged, set in a light tint, opening mark hung in the left margin. Links: either brand color + heavier weight with no underline, or text kept in the dark body color with a thick tinted underline that overlaps the bottom of the letters. Checkboxes/radios: larger than browser default with the brand color on the checked state. Where: VD section 8 first bullet.

15. **Background decoration specifics (p228-232).** Color swap shown on a single pricing card: body becomes the solid brand color, text switches to white plus light tints of that hue, and the footer action strip flips to white. Page sections alternate brand color / white / near-black / light grey. Patterns can run along one edge only (dot pattern along a footer's bottom edge) or sit as a small chunk in one corner; shapes such as a dotted triangle go beside the text column, and a dotted world map sits directly behind centered form content at very low contrast. Where: VD section 8 "Decorate backgrounds".

16. **Intended-size specifics (p209-213).** Icon fix: keep the glyph at its drawn size (24px) and center it in a larger circle (48px) filled with a light tint, icon in a darker shade of the same hue; different hues per feature. Alternative: use an icon set drawn for large sizes, which has more detail and thinner relative strokes. Screenshot scale example: shrinking by 70% turns 16px UI text into about 4px. Remedies pictured: capture at tablet width, crop to a region (shown in a circular lens), or draw a simplified version with text replaced by lines. Favicon: redraw with fewer, thicker strokes for the 16px target. Where: VD section 7 third bullet.

17. **Leveling-up examples (p250-252).** Things the book flags as worth noticing in other people's work: dark inverted datepicker popover on a light UI, submit button placed inside the input's frame, a two-color headline (second line in brand color). Annotated rebuild card: heading `line-height: 1.2`, image cropped with `overflow: hidden`, two-part shadow, uppercase button label with letter-spacing, and a full-width tinted footer strip as the card action instead of a button. Where: VD section 9 (optional, low priority).

## 2. Wrong or distorted

Shadow tokens first, as requested.

- **Single elevation set (DT lines 48-52): matches p183 exactly** (`0 1px 3px`, `0 4px 6px`, `0 5px 15px`, `0 10px 24px`, `0 15px 35px`, all alpha .2). No error.
- **Two-part set (DT lines 55-59 and the Tailwind block): matches p189.** One note: the level-4 tight shadow prints on the page as `hsla(0,0%, .5)` with a gap where a digit would be. `.05` is the only value consistent with the sequence .24, .12, .10, then nothing, and with the statement that the tight shadow should be nearly gone at the top. DT's `.05` is the right reading; add a comment so nobody "fixes" it to .5. Level 5 having a single shadow is also faithful.
- **Elevation-to-component mapping in DT ("1 to 2 buttons/cards, 3 dropdowns/popovers, 4 to 5 modals") does not follow the book's examples.** The book's dropdown uses the level-2 geometry `0 4px 6px` and at a lighter alpha (.1) (p181); level-3 geometry is used for a dialog panel (p239); the modal uses level 5 (p182). Suggested mapping: 1 buttons, 2 dropdowns/raised-button hover, 3 panels/popovers, 4 to 5 modals. Also DT says "level values follow the book's example" for fixed alpha .2; the book itself varies alpha per use (.1 dropdown, .15 dialog).
- **VD section 6 "pressed button loses it" (shadow).** The book's main example reduces the shadow from `0 4px 6px` to `0 1px 3px`; removing it entirely is given as the alternative (p184).
- **VD section 6 "hand-picked color, not translucent white"** is correct for the raised top highlight (p176) but reads as a general rule; the book's own inset lip is translucent white at .15 (p177).
- **VD section 7 colorize recipe drops a step.** Book order: lower contrast, then desaturate, then multiply fill (p205). VD lists only desaturate + multiply.
- **VD section 7 overlay** omits that the overlay's lightness must match the text strategy (p204); as written, someone could put a dark overlay under dark text.
- **VD section 7 "subtle inset shadow or semi-transparent inner border"** is faithful, but note for whoever adds values: p216's two captions are identical in the book (both print the 2px solid border, including under the good example), which is a book error. The only real inner-edge value is on p217.
- **Book misprints not to import:** `.7` tight-shadow alpha on p186/p252 (see item 9) and `letter-spacing: 0.8rem` on p252 (would be about 13px; DT's `0.05em` is sane). The p177 caption lacks `inset`.

## 3. Audit-checklist additions

All for section F unless noted. Each is pass/fail from code or a screenshot.

- [ ] Raised controls (solid buttons) show a lighter top edge that is an opaque tint of the control's own color, and any shadow falls only below (positive y, blur of about 3px or less). Fail: translucent-white highlight on a saturated fill, or a shadow with zero or negative y. (p176)
- [ ] Inset controls (inputs, wells, checkboxes, where depth is used at all) have a dark inset shadow at the top and a lighter bottom lip, not the reverse; nothing mixes raised and inset cues on one element. (p177-178)
- [ ] (Sharpens existing F item) Floating layers are not flat: dropdowns, popovers and modals carry a shadow rather than only a 1px border, and the ordering holds (button < dropdown < dialog < modal). (p181-182)
- [ ] `:active` on shadowed buttons drops to a smaller or no shadow; dragged items gain a shadow and a raised background. (p183-184)
- [ ] In two-part shadows the tight layer's alpha decreases with each level and is absent or near zero at the top level. Fail: same tight shadow copied to every level. (p189)
- [ ] In flat themes, depth shadows are zero-blur, short (about 3px), and an opaque tint of the background rather than translucent black; raised surfaces are lighter than the page, inset ones darker. (p191-192)
- [ ] Overlapping images/avatars have a border in the surface color (about 4px) so edges never touch. (p196)
- [ ] (Sharpens existing F item) Text over a photo is legible across the whole text box, checked against the brightest and darkest regions it crosses; overlay lightness is opposite to the text lightness; any text-shadow used for this has zero offset and a large blur. (p203-206)
- [ ] No icon rendered above about 2x its drawn size; large icon slots use a tinted shape with the icon at native size, or a large-format icon set. (p209)
- [ ] No marketing screenshot scaled so that UI text falls below a readable size (the book's example is 16px text ending up at about 4px; a threshold such as 10px rendered is this reviewer's suggestion, not the book's); favicon is a simplified redraw, not the full logo downsampled. (p210-213)
- [ ] (Sharpens existing F item) User-image grids keep even rows: every image sits in a fixed-ratio box with cover-cropping, centered. Avatars/thumbnails on a similar-colored background have a translucent inner edge (`inset 0 0 0 1px` at about .1 alpha), not a solid colored ring. (p214-217)
- [ ] A shadow is used in place of a border only where the element's fill differs from its background. (p239)
- [ ] No region has both its own background fill and a border separating it from its neighbour (border is redundant). (p240)
- [ ] List rows are separated by spacing or fill before dividers; a fully ruled list counts as a finding. (p238, p241)
- [ ] Section H, empty states (sharpens existing H item): the message tells the user what to do rather than reporting "none found"; exactly one instance of the primary action is visible; page chrome that needs data (tabs, filters, search, sort) is hidden, not just disabled. (p235-236)
- [ ] Section C or F, tables: statuses are tinted pills (dark text on a light tint of the same hue, with a text label), not plain text; non-sortable related columns are merged into stacked primary/secondary cells where the table is wide. (p244-245)
- [ ] Section C: a radio group that is the main decision on the screen (plan, tier, shipping) is presented as selectable cards, with the selected state marked by at least two cues (border/tint plus a check). (p246)
- [ ] Section F: accent borders are used in a fixed set of positions (card top, active nav underline, alert left edge, short bar under headline, page top) and with one consistent color and thickness per position. (p224-226)
- [ ] Section F: background patterns/illustrations sit at very low contrast and never reduce text contrast below the 4.5:1 / 3:1 thresholds where they pass behind text. (p230-232)
- [ ] Section F: gradients use two hues no more than about 30 degrees apart (already in VD, absent from AC). (p229)

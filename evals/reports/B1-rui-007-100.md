# B1 gap review: Refactoring UI, PDF pages 007-100

Scope: Starting from Scratch, Hierarchy is Everything, Layout and Spacing. Every existing page image in the range was viewed (007-032, 035-062, 065-099). Pages 033, 034, 063, 064, 100 do not exist as files; 011, 015, 027, 041(text only), 045, 052(text only), 053, 075, 083, 091 are blank or text-only.
Compared against: `visual-design.md` (VD), `design-tokens.md` (DT), `audit-checklist.md` (AC).

## 1. Missing or under-specified (priority order)

1. **p61 - Button hierarchy changes with the background it sits on.** The illustration is a 3x3 matrix (primary / secondary / tertiary across white, dark-grey, and colored-gradient backgrounds):
   - White bg: primary = solid brand fill + white text; secondary = white button, brand-colored border and text; tertiary = brand-colored text, underlined, no box.
   - Dark bg: primary = solid bright accent fill; secondary = transparent with a mid-grey outline and white text; tertiary = bare white text.
   - Colored/gradient bg: primary = **white fill with brand-colored text** (inverted); secondary = **semi-transparent white fill** with white text, no border; tertiary = bare white text.
   VD section 2 "Actions follow a pyramid" only describes the white-background case. Add the dark and colored variants there; add a note in DT usage reminders (this is the one legitimate place a translucent-white *fill* appears, as opposed to translucent-white *text*, which is banned).

2. **p62 - Destructive-action treatments are concrete, and the tertiary one is not red.** Shown: primary = solid red + white text; secondary = white button with red text (subtle border); tertiary = plain **grey** text, no red at all. On p61 the fixed card shows "Delete Listing" as a link-style text action in the normal link color, pushed to the opposite (left) side of the button row from Edit/Publish. The confirmation dialog shows: title, consequence sentence, then a tinted footer strip with right-aligned actions - "Cancel" as bare tertiary text and the red solid destructive button last. VD says only "give it secondary/tertiary treatment"; add these three variants, the "separate it spatially from the primary" placement, and the dialog anatomy to VD section 2.

3. **p96-99 - Ambiguous-spacing rule has measurable ratios.** All four examples use an outside:inside ratio of at least 2:1, mostly 3:1 or more:
   - Form: label-to-input 10px vs input-to-next-label 20px (bad: 20/20).
   - Article heading: 36px above, 12px below (bad: 24/24).
   - Bulleted list: 36px between items when the line box is 24px (bad: item gap = line-height, 24/24).
   - Horizontal icon+count pairs: 6px icon-to-number, 36px between pairs (bad: 16/16).
   VD section 3 states the principle with no numbers. Add "aim for outside gap >= 2x inside gap; never equal" plus the four value pairs. Also p96: when groups have an explicit separator (border/background) the rule is relaxed - the spacing rule applies specifically to groups with no visible divider. DT could add a note: "pick inside/outside gaps at least one, ideally two, scale steps apart".

4. **p94-95 - Button padding values per size.** Proportional (bad, equivalent to em padding): 20px font -> 15/20 padding, 16 -> 12/16, 14 -> 10.5/14, 12 -> 9/12. Hand-tuned (good): 20px font -> `15px 30px`; 16px -> `12px 16px`; 14px -> `8px 10px`; 12px -> `6px 8px`. Note the horizontal padding grows much faster than vertical at the large end (ratio 2:1) and collapses at the small end. VD section 3 says this in words only; DT has no button-size tokens. Add a button size table to DT (tune to the scale, e.g. lg 16/32, md 12/16, sm 8/12, xs 4/8).

5. **p92-94 - Responsive headline numbers.** Desktop: body 18px, headline 45px (2.5x). Mobile: body 14px; 2.5em renders 35px (too big); recommended mobile headline 20-24px, i.e. only ~1.5-1.7x body. Rule of thumb for VD section 3 / DT type scale: headline:body ratio ~2.5 on desktop, ~1.5-1.7 on phones; body text drops only ~20% while headlines drop ~45-55%.

6. **p38-40 - Worked before/after for "size isn't everything" with real values.**
   - Before (all weight 400): title 30px, body 16px, price 24px, fine print 14px.
   - After: title 24px/700, price 18px/700, body and "per person" 16-18px/400, fine print stays readable and is demoted by color instead of size.
   - Text colors used: dark `hsl(202, 57%, 15%)`, grey `hsl(201, 23%, 34%)`, light grey `hsl(203, 15%, 47%)`. Note the dark is strongly saturated (57%) and the "light grey" is still under 50% lightness on a white/near-white card - tertiary text in the book is not pale.
   Takeaway for VD section 2: shrink the primary element and bolden it; raise secondary text size back up and demote with color. The range of sizes in the fixed version is 16-24px (1.5x), not 14-30px (2.1x). DT: `--text-tertiary` comment could cite ~47% lightness as the book's floor for tertiary text on white.

7. **p42-44 - Text on a colored panel, concrete values.** Bad: `hsl(0, 0%, 78%)` grey on a teal panel; also bad: `hsla(0, 0%, 100%, 0.6)` (p44 zoom shows the background pattern visibly bleeding through the letterforms). Good: `hsl(183, 70%, 84%)` - same hue as the panel, **high saturation (70%) and high lightness (84%)**. VD says "adjust saturation/lightness" without direction; DT says "a lighter/less saturated tint" - the book's example keeps saturation high (see section 2 below). p43 also shows the mental model: place the text colors on a lightness ramp running from the background color to the max-contrast color; secondary text sits closer to the background end.

8. **p57-59 - Weight/contrast compensation values.**
   - Icons next to nav text: text `hsl(212, 20%, 13%)`, icon same hue and saturation at `hsl(212, 20%, 68%)`. I.e. icon is ~55 lightness points lighter than its label, same hue. The + icons in the track list get the same treatment.
   - Dividers: `1px solid hsl(206, 16%, 74%)` = too dark/noisy; `1px solid hsl(210, 23%, 95%)` = too faint; `2px solid hsl(210, 23%, 95%)` = balanced.
   - p56: bold glyph covers ~90px2 vs ~50px2 for regular at the same size - emphasis is a function of inked surface area, which is why the rule generalises to icons and borders.
   VD section 2 has the principle; add the values. DT: `--border-2` comment should pair 2px with the ~95% lightness grey (`--grey-100`/`--border-subtle`), and add an `--icon-muted` role mapped to ~grey-400.

9. **p70 vs p74 - What a spacing-system fix looks like.** Before, one card uses nine different gaps: 26, 24, 26, 12, 15, 21, 25, 13, 22px (left padding 26 vs right 24). After, the same card uses only **two** values: 24px (card padding all four sides, above and below the section divider) and 12px (between tightly related lines). Add to VD section 3 / DT: a single component should resolve to 2-3 scale values, with symmetric container padding.

10. **p71-72 - Why non-linear, with numbers.** Icon in a button at 16/20/24px = +/-20% and visibly different; card 500 -> 520px = 4% and invisible (8x less significant than 12 -> 16px, which is 33%). "Everything a multiple of 4px" is called out as insufficient. p73: the scale is defined as multipliers of 16: 0.25, 0.5, 0.75, 1, 1.5, 2, 3, 4, 6, 8, 12, 16, 24, 32, 40, 48. DT lists the px values but not the multipliers (useful when the base is not 16) and does not warn against the plain 4px-grid approach.

11. **p30-31 - Elimination procedure is a loop, not one comparison.** Guess a value (16px icon), compare with both neighbours (12, 24). If the middle wins, done. If an outer value wins (24), re-centre on it and compare again with its neighbours (16, 24, 32) before committing. VD section 1 stops after the first comparison. p29-30 also give starter sets: icon/small sizing options 12, 16, 24, 32px; an example 8-step type scale 12, 14, 16, 18, 20, 24, 32, 48; a palette of 10 pre-picked shades per color shown as two rows of five (dark to light).

12. **p37 - The "after" dashboard shows a bundle of specific moves** (VD section 2, opening bullet, currently abstract):
   - Summary stats moved into one solid colored panel; each stat = tiny uppercase letter-spaced label, large light-weight number, small delta beneath.
   - Timestamp ("as of ...") pulled away from the title to the far right and shrunk.
   - Active nav item bold/dark, the rest grey; active sub-tab gets a pill background instead of being same-weight text.
   - Table headers become small uppercase grey; ticker = bold primary with its long name as a grey second line in the same cell; gain/loss amount and gain/loss % merged into one cell (amount over percent, colored).
   - Row actions demoted from solid blue "Buy" + solid red "Sell" on every row to two quiet outline buttons.
   The last point deserves its own rule: **repeated per-row actions are never primary** - solid/semantic-colored buttons repeated down a table create a wall of color.

13. **p49-51 - Label patterns, exact treatments.**
   - Contact card: name largest and dark; role in the accent color (color, not a label, signals it is a different kind of data); email and phone small grey; no labels at all.
   - Label folded into value: bold number + regular-weight unit ("**12** left in stock", "**3** Bedrooms"), optionally led by a small outline icon that replaces the label (bed/bath icons).
   - Dashboard stat: label = small uppercase, letter-spaced, grey, placed *above*; value = large and bold with its unit set smaller ("**82** BPM"). Bad version had the label bold and bigger than the value.
   - Spec sheet (p51): category name bold dark in a left column; in the right column each line is a bold dark label followed by a regular-weight, slightly lighter value - the value is only one step lighter, not tertiary.
   VD section 2 covers the ideas but none of the unit/number split, icon-as-label, or uppercase-label-above-value mechanics.

14. **p54-55 - Page-title size and hidden headings.** App page title ("Manage Account") shown at 24px (bad) vs **16px** (good) - the h1 ends up smaller than the 18px-ish section title inside the card and the same size as tab labels. Also missing from VD: section titles may be kept in the markup for accessibility but **visually hidden** when the content is self-explanatory. Add both to VD section 2 "Visual hierarchy is not document hierarchy".

15. **p46-47 - De-emphasis examples.** Nav: coloring the active item alone fails while inactive items stay dark/bold; fix is inactive items in a soft grey, active keeps the brand color. Sidebar: the bad version puts the step list in a white card equal to the main white card; the good version removes the card so the sidebar sits directly on the page background and only the main content is a raised white surface. VD mentions both in a parenthesis; AC has no check for "secondary column has the same surface treatment as primary content".

16. **p76-81 - Width handling patterns.**
   - Cart page: stretched to ~1200px it puts the item name at far left and price at far right, breaking their association; the fix is a narrow (~1/3 viewport) centred column, header included. Reason to record: wide layouts break label-value/row associations, not just aesthetics.
   - p77: full-width nav bar over a narrow centred login card is explicitly fine.
   - p78-79: design at ~400px, then on desktop the *same* column is simply centred at roughly the same width with the hero band going full-bleed behind it; only the hamburger became inline nav links.
   - p80-81: settings form. Instead of widening inputs, use a two-column row per section: left = section title + muted help text (narrow), right = the fields at their optimal width; horizontal rule between sections.
   VD section 3 mentions "form + supporting text" in six words; spell out the settings-section pattern.

17. **p84-90 - Grid specifics.** 12-col grid = 8.33% per column. Failure demos: a 25% sidebar grows wastefully on wide screens and wraps/truncates its labels on narrow ones; a 6-col login card switched to 8-col at the medium breakpoint becomes *wider on medium screens than on large ones*. Fix: fixed-width sidebar, main area flexes and uses its own internal grid - illustration shows invoice cards going 4-up to 2-up as the window narrows while the sidebar is unchanged; login card `max-width: ~500px`, shrinking only below that. Inside components: avatar is a fixed width while the text column flexes (p87). VD section 3 has the rule; add the "wider on medium than large" symptom and "cards reflow by count, not by stretching" as the observable behaviours.

18. **p66-69 - Whitespace examples.** Good card: roughly 2x the padding of the cramped one, and the intro block and the form block are split by a full-bleed divider with generous space on both sides. p68 also shows that "too much" is a real state to pass through (rows floating apart) before settling - and that the final version tightens *within* the rating list while keeping large padding around the card and between list and CTA block (links to the ambiguous-spacing rule). p69 dense example: compactness is achieved with small uppercase labels over bold values in a tight 3-col stat grid and thin row dividers, not by shrinking padding uniformly.

19. **p26 - How to choose the personality when there is no gut feel.** Look at other products the target audience already uses and match that register; do not borrow from direct competitors (avoids looking like a knock-off). Missing from VD section 1.

20. **p21-25 - Personality illustrations add a few signals beyond the four levers.** Serif used for the headline only with sans body and UI; rounded sans paired with pill-shaped buttons; the "formal" example combines zero radius + wide-tracked uppercase brand text + muted dark button; the "playful" example combines large radius + pill buttons + circular background shape. Button shape follows the radius decision (pill vs square). Low priority.

21. **p12-14 - Low-fidelity specifics.** Sketch with a thick marker on paper to make detail impossible; treat sketches/wireframes as disposable and stop once a decision is made. p13 greyscale example shows selected state carried by border weight + check icon + slightly raised card, and primary button by a dark fill - color later only re-tints these. VD section 1 lacks the "selected/primary states must already read in greyscale" test.

22. **p18-19 - Pessimist example.** Comment box designed with a drag-and-drop attachment zone vs shipped without it. Record as a check: every affordance in a mock must be in the build scope. Low priority.

## 2. Wrong or distorted

1. **DT usage reminders, "Text on a colored panel: a lighter/less saturated tint of the panel's hue"** - p44's correct example is `hsl(183, 70%, 84%)` on a teal panel: same hue, lighter, but saturation kept high (70%). "Less saturated" pushes toward the greyish look the chapter is warning against. Should read "same hue, lighter, saturation tuned by eye (the book's example keeps it high)".
2. **VD section 1, "try a value, compare its two neighbours, keep the winner"** - truncates the method (p31). If a neighbour wins you must re-run with it as the new middle. As written it can stop one step short.
3. **VD section 2 / AC section C, destructive actions** - not wrong, but the implication that a demoted destructive action is still red is not what p61-62 show: tertiary destructive is neutral grey or normal link color; only the secondary variant keeps red (as text).
4. **DT "No two neighbours closer than ~25%"** - matches the book's sentence (p72), but the book's own scale (p73) breaks it at the top: 640 -> 768 is 20%, 512 -> 640 is exactly 25%. Harmless, but the DT line should say "about 25% (looser at the very top)" so nobody "fixes" the scale.
5. **DT type scale tagged [RUI]** - fine for the book's later chapter, but note p29 shows a different illustrative scale (12, 14, 16, 18, 20, 24, 32, 48). Not an error; do not treat the 11-step scale as the only book-sanctioned one.
6. Nothing else in my range is misstated; VD sections 1-3 are faithful in principle and only thin on numbers.

## 3. Audit-checklist additions

Section C (hierarchy):
- [ ] Font-size spread inside a single card/component is modest (roughly <= 1.5-2x between largest and smallest); emphasis is carried by weight 600-700 and color. Fail: 30px/400 title next to 14px fine print (p38-39).
- [ ] Secondary/tertiary text is demoted by color before size; nothing essential under ~14px; tertiary text on white not lighter than ~47-50% lightness (p39-40).
- [ ] Inactive nav items are visibly softer (grey) than the active one; the active item is not distinguished by hue alone among equally dark/bold siblings (p46).
- [ ] Sidebars / secondary columns do not share the same raised-card surface as the primary content (p47).
- [ ] Repeated row-level actions (table rows, list items) use secondary/tertiary styling; no solid or semantic-colored buttons repeated per row (p36-37).
- [ ] Buttons on dark or colored backgrounds follow the adapted pyramid: primary inverted/solid, secondary outline or translucent fill, tertiary bare text (p61).
- [ ] Non-primary destructive actions are neutral or red-text only and are spatially separated from the primary action; the solid red button appears only in the confirmation dialog, where cancel is tertiary (p61-62).
- [ ] Stat/metric blocks: label is smaller, lighter, (often uppercase+tracked) and the value is the largest/boldest thing; unit is smaller than the number. Fail: bold label over a plain value (p51).
- [ ] Values with units/counts style the number bold and the unit regular ("**12** left in stock") rather than "Label: value" (p49-50).
- [ ] App page titles are not oversized: compare h1 size with the content's own headings; ~16-20px is normal in app chrome (p54-55).
- [ ] Icon color beside text is clearly lighter than the text (same hue, much higher lightness), not the same dark color (p57).
- [ ] Dividers: no dark 1px rules (around 75% lightness or darker on white). Prefer ~95% lightness at 2px, or spacing (p58-59).
- [ ] Muted text on colored panels shares the panel's hue; no neutral grey (`hsl(*, 0%, *)`) and no `rgba/hsla(white, <1)` text, especially over images or patterns (p42-44).

Section D (layout and spacing):
- [ ] Measure the gaps in one representative component: they resolve to 2-3 scale values and container padding is symmetric. Fail: 26/24/15/21/25/13/22 style drift (p70, p74).
- [ ] Outside-group gap is at least ~2x the inside-group gap: label-input vs field-field (10 vs 20), heading above vs below (36 vs 12), list-item gap vs line-height (36 vs 24), icon-count vs pair-pair (6 vs 36). Equal values = fail (p97-99).
- [ ] Horizontal clusters (icon + count, avatar + name, meta items) are checked for the same rule, not only vertical stacks (p99).
- [ ] Wide layouts do not pull related items to opposite edges (item name far left, price far right across >800px) (p76-77).
- [ ] Long forms on wide screens use a section-description column + fields column instead of full-width inputs (p80-81).
- [ ] No percentage-width sidebars or avatars/media inside cards; grep for `%`/fractional column classes on elements whose content has a natural size (p85-87).
- [ ] Resize test: no element is wider at a medium breakpoint than at a large one; cards/forms use `max-width` rather than per-breakpoint column spans (p88-90).
- [ ] Main-area card grids reflow by changing column count as width changes; the sidebar stays constant (p87).
- [ ] Button sizes are not pure zoom: grep for `em`-based padding on buttons; large variants have proportionally more horizontal padding (about 2x vertical), small variants tighter (p95).
- [ ] Headline:body ratio shrinks on small screens (about 2.5x desktop to about 1.5-1.7x mobile); headlines are not defined in `em` relative to body (p92-94).
- [ ] Whitespace check is made in full-page context, not per element; card padding is comfortably larger than the gaps between the card's internal items (p66-69).

Section F / system pass:
- [ ] Spacing values being "multiples of 4" is not sufficient; flag scales with many near-neighbours at the large end (e.g. 120/124/128) (p71).

Process (new short section or under "How to run an audit"):
- [ ] Greyscale test: desaturate a screenshot; primary action, selected state, and hierarchy should still read (p13).
- [ ] Every affordance visible in the UI is actually functional/in scope (no placeholder features) (p18-19).

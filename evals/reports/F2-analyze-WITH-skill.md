# UI/UX audit: Shiftboard (React + Tailwind staff scheduling app)

**Screens reviewed:** schedule (`#/schedule`), team (`#/team`), shift (`#/shift/12`, shift detail / edit form), settings (`#/settings`), plus shared chrome (TopBar, SideNav, Layout, Toggle, WeekGrid).   **Evidence:** all source read / scan.py (markup, utility-class and words passes) / contrast.py on 32 pairs / screenshots at 1280px and 500px (raw headless Chrome; no true 400px render, see Not verified) / no live interaction.
**Assumed top user tasks (inferred; the user is a cafe manager):** 1) fill an open shift or change who works a shift; 2) build the week and publish it to the crew; 3) check each person's hours and cost against contract, and contact them.

## Verdict

Shiftboard has one well-built core (the week grid, the time-off empty state, and the archive confirmation all use the theme tokens, real links and buttons, labels and focus rings) wrapped in chrome and forms that work against the manager. The biggest problem is the shift form: it silently requires four bureaucratic fields and an `HH:MM:SS` time, answers every mistake with "Invalid input.", shows a permanent fake error banner, and puts a no-confirmation solid red Delete next to Submit, so the number one task (covering an open shift) is both blocked and dangerous. Around that, navigation is unreachable by keyboard, named in in-jokes ("The Grid", "Crew HQ", "Control Room") that match no screen title, and the one action that finishes the week ("Publish week") is the only button styled to look disabled. The design system exists in the Tailwind theme but most components bypass it with 76 distinct one-off values, which is where the inconsistent look comes from.

## Top fixes

1. **Make the shift form finishable and safe** - it is top task 1 and currently fails silently. Drop or make optional Assignment mode, Cost center, Approving manager ID and Reason (cost center is already known); accept `13:00` and `1pm` and normalize; put a plain-words message beside the offending field; delete the hard-coded error banner; move Delete away from Submit as a quiet text button with a confirm step (or undo). Effort M. Resolves #32, #33, #34, #35, #38.
2. **Real controls with names** - replace `div onClick` nav items, open-slot rows and the Toggle with `<a>` / `<button role="switch">`; add `<label>` to the 14 placeholder-only controls; give the 7 icon buttons `aria-label`s; stop stripping focus with `outline-none` (reuse the `focus-visible:ring-2 ring-brand-500` pattern already in WeekGrid). Effort M. Resolves #1, #2, #3, #4.
3. **One primary action on Schedule: Publish week** - solid brand fill for "Publish week"; "Add shift" secondary outline; "Copy last week" and "Export" tertiary; one radius. Effort S. Resolves #19 and part of #17.
4. **Plain navigation that says where you are** - rename to Schedule / Team / Settings, make each screen's `<h1>` match (Team has no title at all), set `document.title` per route, mark the current item with two cues (white text + tinted background or left accent bar), put the logo top-left linking to `#/schedule`, and cut the top bar to about 4 named utilities with promos moved out. Effort M. Resolves #6, #7, #8, #9, #27 and most of #5.
5. **Surface the facts managers need and cut the filler** - delete the 78-word welcome paragraph and shrink the 76-word notifications blurb to one sentence; move "4 unfilled" and "Projected overtime $348.38" out of the 11px footer into the stats band; restyle the band with white / brand-100 text instead of grey on blue; use one word ("shift") everywhere. Effort S. Resolves #22, #20, #23, #41, #10.
6. **Fold one-off values into the existing theme** - replace `bg-[#2f6fed]` with `bg-brand-600`, `text-black` with `text-ink-900`, greys with the `ink` scale; extend the theme with a type scale (about 12/14/16/20/24) and use Tailwind's default spacing steps; remove `font-light` from the root; fix the Team table width and drop `min-w-[1240px]` in favour of a fixed-width sidebar and responsive variants. Effort L. Resolves #11, #12, #13, #14, #15, #17, #29.

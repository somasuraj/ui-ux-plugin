# B2 gap review: Refactoring UI pp. 101-170 (Designing Text, Working with Color)

Pages viewed: every image p101-p168. p135, p136, p169, p170 do not exist in the folder. p101/p137 are chapter title pages; p113, p117, p121, p161 are blank; p107, p112, p141, p147, p157, p160 are text only.
Targets: VD = visual-design.md, DT = design-tokens.md, AC = audit-checklist.md.
Ratios marked "(computed)" are my own WCAG calculations, not from the book.

## 1. Missing or under-specified (priority order)

1. **Perceived-brightness formula (p153).** `sqrt(0.299*r^2 + 0.587*g^2 + 0.114*b^2) / 255` with r,g,b in 0-255. Entirely absent. It is the objective way to confirm two shades with equal HSL lightness will not read as equally light (yellow hsl(60,100%,50%) vs blue hsl(240,100%,50%) is the book's demo). The p154 chart plots 100%-sat / 50%-L hues: three maxima (60/180/300) and three minima (0/120/240). Applying the formula (computed): yellow 0.94, cyan 0.84, green 0.77, magenta 0.64, red 0.55, blue 0.34. -> VD section 5 "Perceived brightness" bullet; DT palette method paragraph.

2. **Grey-text contrast thresholds on white (p162 table).** Pure grey hsl(0,0%,L): L54% = 3.45:1 fails normal text; L42% = 5.41:1 AA; L33% = 7.57:1 AAA. Large text: L59% = 2.96:1 fail; L54% = 3.45:1 AA; L42% = 5.41:1 AAA. Working rule: normal-size grey text on white needs lightness at or below roughly 45%; large text roughly 55%. -> VD section 5 "Accessible" bullet; DT usage reminders (directly affects `--text-tertiary`, see section 2 below).

3. **Status badge numbers behind "flip the contrast" (p163-164).** White text on mid-tone green / yellow / pink-red pills measures 2.25 / 1.56 / 3.14 (all fail). Darkening the fills until white passes gives 5.97 / 5.07 / 5.34 but the pills become the loudest thing in the table row. Dark same-hue text on a pale tint gives 9.01 / 9.78 / 12.32 (AAA) and sits quietly. Tells the designer that white-on-saturated is not "slightly off", it is far off, and yellow is hopeless with white text. -> VD section 5; DT usage reminders.

4. **Coloured text on a coloured panel: worked values (p165).** Panel hsl(240,34%,34%). Same-hue secondary text has to go to hsl(240,44%,89%) to be safe (8.37:1) and is then indistinguishable from the white primary text. Rotating toward cyan and raising saturation, hsl(188,100%,85%), gives 8.71:1 and still reads as a colour. Note the rotation here is ~52 degrees and saturation goes UP to 100%, so the book's own example exceeds its p157 cap of 20-30 degrees; the book does not reconcile the two (my reading: the cap is about shades within one palette scale, not about choosing an accent text colour on a panel). DT's reminder ("lighter/less saturated tint of the panel's hue") describes only the approach the book marks as the failing one for this case. -> VD section 5 last sentence of "Accessible"; DT usage reminder 2.

5. **Hue-rotation worked values (p155-156).** Lighten without losing intensity: hsl(210,100%,50%) -> hsl(190,100%,50%) (20 degrees toward 180, S and L untouched), shown as the top stop of an icon gradient, contrasted with the washed-out alternative hsl(210,100%,75%). Darken: hsl(50,100%,50%) -> hsl(32,100%,50%). Combined (hue + lightness): panel hsl(221,49%,33%) with accent text hsl(194,49%,73%), i.e. 27 degrees of rotation, same saturation, +40 lightness. Yellow 10-step scale: keeping hue fixed gives olive/khaki darks (marked wrong); sliding hue toward orange as lightness drops gives amber-to-brown darks (marked right). Also an unstated technique: build two-stop gradients by rotating hue rather than changing lightness. -> VD section 5; DT palette method; VD section 8 gradient bullet.

6. **Saturation curve shape (p152 chart).** The corrected curve is a steep U, not a nudge: reading the plot, roughly 50% at the 50%-L base, ~57% one step out, ~72% two steps out, ~93% at the lightest and darkest shades. Symmetric on both sides. If the base is already near 100% saturation there is no headroom, which is precisely when hue rotation takes over (p153). DT/VD say "raise saturation" without magnitude or the fallback. -> VD section 5; DT palette method.

7. **Tinted-grey reference values (p158-159).** Cool set: H 207-210, S 15/12/12/16/21 at L 28/43/58/76/88. Warm set: H 39-41 with the identical S and L values. Neutral: S 0. So a "slight" temperature is S ~12% mid-scale rising to ~15-21% at the ends. Real-UI sample on p158 goes much heavier: hsl(212,56%,16%) darkest text, hsl(212,18%,35%) secondary text, hsl(210,32%,93%) page bg, hsl(210,38%,97%) panel bg. DT has only a cool example and no warm recipe (H ~40). -> DT palette template (add warm variant comment); VD section 5 greys bullet.

8. **Baseline alignment CSS and when it bites (p118-120).** The fix is literally `align-items: baseline` instead of `align-items: center` on the flex row holding a card title plus smaller action links. The misalignment is tolerable when the two texts are far apart (title left, links right) and obvious when they sit next to each other. -> VD section 4 baseline bullet.

9. **Letter-spacing values (p132-134).** The book's only values are `-0.05em` (tight), `0`, `+0.05em` (wide). Headline set in a text family (Open Sans) gets `-0.05em` to imitate a display family (Oswald); all-caps label gets `+0.05em`. Reason for the caps rule: caps lack ascender/descender variety so shapes are harder to tell apart. One-way rule missing from VD: never try the reverse, a headline/condensed family does not become legible at small sizes by widening tracking. -> VD section 4 letter-spacing bullet; DT `--tracking-*`.

10. **Line-height concrete pairs (p122-125).** Reference case: 16px text / 24px line = 1.5. Narrow column 1.5, wide column 2. Small body text: 1.25 marked wrong, 1.75 marked right. Two-line bold headline: 1.5 marked wrong, 1 marked right. VD says headlines "1 to 1.25"; the book's target is 1. DT has no token for 2 although VD says "up to ~2". -> DT add `--leading-loose: 2`; VD section 4.

11. **Type-scale before/after (p102, p106).** One product card's 9 text elements used 8 distinct sizes (11, 12, 13, 14, 15, 17, 18, 26px); after, the same card uses 4 (14, 16, 18, 24), with 14 doing the work of five former sizes. Gives a target: a single component should land on about 3-4 sizes, and near-neighbours (13/14/15) are the smell. -> VD section 4 first bullet; AC section E.

12. **Why not modular scales, with numbers (p103-104).** Golden ratio from 16px: 9.89, 16, 25.89, 41.89, 67.77, 109.66px (huge holes, fractional). 4:5 yields 31.25, 39.063, 48.828. Rounded 3:4 yields only 12, 16, 21, 28 so you lack a size between 12-16 and 16-21. If a ratio scale is used anyway, round the values by hand when defining tokens to avoid cross-browser off-by-one. Em nesting example: 1.25em parent x 0.875em child = 17.5px, off-scale (p107). -> VD section 4 first bullet.

13. **Line length (p114-116).** Bad example is ~120 characters per line. Book's snippet: a centered intro paragraph under a section headline gets `max-width: 34em` while the 3-column feature grid under it keeps the full container width (`max-width: none` is the marked-wrong state). Samples shown at 45-55, 55-65 and 65-75 cpl are all acceptable. -> VD section 4 line-length bullet (add the centered-intro case).

14. **Right-aligned numeric columns (p130).** In the corrected table the column HEADERS are right-aligned along with the figures, and the point is that decimal points stack vertically. (Inference, not in book: that only works with a fixed number of decimals and tabular figures.) -> VD section 4 alignment bullet.

15. **Justified text CSS (p130-131).** `hyphens: none` is the marked-wrong state (rivers between words), `hyphens: auto` the fix; justified is only recommended for a deliberate print/magazine look. -> VD section 4.

16. **Centering limits shown (p128-129).** Centered 2-line feature blurbs are fine; a 6-line centered block is marked wrong and fixed by left-aligning the text under its (still left-placed) icon. In a row of three centered blurbs where one runs to 4 lines, the fix shown is cutting the copy to 2 lines so all three match. VD has the rule; missing is "all sibling blocks should wrap to the same line count". -> VD section 4.

17. **Link treatment in link-dense UIs (p126-127).** Video grid: every title and channel name in blue bold is marked wrong. Fix: titles dark and semibold, channel names a medium-dark grey at medium weight, metadata light grey, no blue anywhere. Tertiary links (channel name) show underline only on hover. Inline links inside prose keep colour plus underline. -> VD section 4 link bullet (add the prose exception explicitly).

18. **Palette size and mapping (p143-148).** A modest chat UI is shown mapped to ~17 swatches: 1 green, 3 blues, 2 teals, 1 red, 5 greys, 5 yellows. Five named grey roles in a form screen: darkest (labels/headings), dark (help text), mid (borders), light (button/well fill), lightest (page bg). Complex UIs may need up to ~10 colours x 5-10 shades; categorising UIs (chart series, calendar events, tags) need extra accent hues beyond the semantic ones. Accent for "new feature" badges: teal, pink or yellow. VD lists semantic colours but not the categorical-accent need or the upper bound. -> VD section 5 palette bullet.

19. **Shade-picking method details (p149-151).** Base 500: shown as the middle of three buttons, too dark and too light both rejected; explicitly no "start at 50% lightness" rule (DT's example uses exactly L 50% for primary-500 and grey-500, which is fine but should not be presented as a rule). Alert test piece: the book points at 900 = bold title text and 100 = fill; the illustration also appears (my reading) to use a mid-dark shade (~600-700) for the body line and a light shade (~200-300) for the border. Greys: base shade is not important; pick 900 as the darkest body-text colour and 100 as a subtle off-white page background, then fill inward. Nine shades chosen because it bisects cleanly (900/500/100 -> 700/300 -> 800/600/400/200). -> DT palette method; VD section 5.

20. **HSL basics useful for debugging (p138-140).** A one-hue chart set: hsl(220,95%,34%), hsl(220,65%,61%), hsl(220,69%,80%): same hue, saturation not monotonic. At S 0% hue is meaningless. HSB vs HSL conversion trap: HSB 100% brightness at 100% saturation equals HSL 50% lightness, so numbers copied from a design tool's HSB picker are wrong in CSS. -> VD section 5 first bullet.

21. **Colour-blind examples (p166-168).** Under red-green simulation the up/down metric pills become identical grey-green; fix is an arrow icon inside the pill next to the number. Under blue-yellow simulation a blue/green/orange donut collapses to two near-identical teals plus pink; fix is one hue in three clearly separated lightness steps (light / mid / very dark). VD states the rule; missing is "single hue, 3 lightness steps" as the concrete chart recipe and the simulation check. -> VD section 5 last bullet.

22. **Font filter numbers (p109-111).** Setting "number of styles" to 10+ removes ~85% of Google Fonts and leaves fewer than 50 sans-serifs. Legibility diagram: display faces (Futura PT) have shorter x-height and tighter tracking; UI faces (Proxima Nova) taller x-height and looser tracking. "Steal" technique: inspect `font-family` in devtools on sites you admire. Sort-by-popularity is specifically suggested for choosing a non-neutral (serif/personality) face. -> VD section 4 fonts bullet (minor).

## 2. Wrong or distorted

1. **DT success scale rotates hue the wrong way on both sides (book p155-157).** Values: 100 = H145, 500 = H148, 800 = H152. For a base at 148 the nearest bright hue is 180 and the nearest dark hue is 120. Book method: lighter shades move toward 180 (hue should increase), darker shades toward 120 (hue should decrease). DT does the opposite in both directions. Corrected direction would be roughly 100 at ~152-158 and 800 at ~138-144.

2. **DT warning scale loses saturation as it darkens (p152, p160).** S is 100 / 92 / 84 for 100 / 500 / 800. Book requires saturation at 800 to be at or above the 500 value. Hue direction (48 -> 42 -> 30) is correct and matches the book's 50 -> 32 example.

3. **DT danger-800 at H356 (p156).** Red sits on a dark minimum (0), so darkening needs no rotation; 356 drifts toward magenta, a bright hue. Small (4 degrees) but in the wrong direction; keep at 0 or move slightly toward orange-free red.

4. **Primary and grey scales are consistent with the book.** Primary: 205 <- 211 -> 220 (toward 180 when lighter, toward 240 when darker), total swing 15 degrees, S 95 / 80 / 88 is U-shaped. Grey: S 40 -> 16 -> 44 U-shaped, comparable to p158's real-UI values. One caveat: the primary U is much shallower on the dark side than p152 shows, acceptable because the base is already 80%.

5. **DT `--text-tertiary` note understates a failure (p162).** grey-500 hsl(212,16%,50%) on white is ~4.2:1 (computed), and lower on `--surface-page`; the book's table puts L54% at 3.45 and L42% at 5.41. That is a fail for normal-size text, not "borderline". Either darken tertiary to about L45% or restrict it to 18px+ text in the token comment.

6. **DT "500 works as a button background" vs white label contrast (p163).** With white text (computed): primary-500 ~4.1:1, success-500 ~3.5:1, warning-500 ~1.8:1, danger-500 ~4.6:1. Three of four fail 4.5:1 for a normal-size button label, which is exactly the trap p163 describes. Needs a note: use 600 for solid buttons with white text (primary-600 is ~5.6:1), or dark text on warning.

7. **DT `--tracking-tight: -0.02em` is not the book's value (p133).** Book shows -0.05em for the headline case. -0.02em is a defensible softer default but should not sit under an [RUI] provenance; `--tracking-caps: 0.05em` matches p134.

8. **VD "big headlines can sit at 1 to 1.25" (p125).** Book's correct example is exactly 1, with 1.5 as the wrong one. Not wrong, but DT's "1 to 1.15 for large display" and VD's "1 to 1.25" disagree with each other.

9. **VD/DT "large text (~18px+)" (p162).** Faithful to the book. For audits note the book's figure is looser than WCAG's actual definition (24px regular, or ~18.66px bold); an auditor applying 3:1 to 18px regular text would pass things WCAG fails. Outside-the-book correction, flag rather than silently change.

10. **DT usage reminder 2 contradicts p165 for the high-contrast case.** See item 1.4: same-hue, less-saturated tint is the book's marked-wrong option when the secondary text must clear AA on a dark panel; rotate hue toward 60/180/300 and keep saturation high. (The same-hue advice comes from the hierarchy chapter and is fine for de-emphasised text; the two cases need distinguishing.)

11. **VD section 2 "bold red primary only in the confirmation step" vs p146 (low severity).** The in-range destructive confirm dialog shows the confirm button as dark-red text on a pale red tint (flipped contrast) beside a plain-link Cancel, with a red top accent border and red icon carrying the danger signal; not a solid red button. Solid red is allowed, not required, at the confirm step.

## 3. Audit-checklist additions

Section E (typography):
- [ ] No single component uses more than ~4 font sizes; no near-neighbour sizes (e.g. 13/14/15 or 17/18) coexist anywhere. (p102/106)
- [ ] No `font-size` in em on elements that can nest; computed sizes all land on the scale (watch for fractional computed px such as 17.5). (p107)
- [ ] Flex rows mixing font sizes use `align-items: baseline`, not `center`; check especially where the two texts are adjacent. (p118-120)
- [ ] Line-height by case: small/body text >= 1.5 (1.25 is a fail); paragraphs wider than ~75 characters > 1.5 (toward 2); multi-line headlines <= ~1.25 (1.5 is a fail). (p123-125)
- [ ] No paragraph exceeds ~75 characters per line (120 is the book's fail example); centered intro text under a wide section is capped (~34em) independently of its container. (p114-116)
- [ ] Any `text-align: justify` is paired with `hyphens: auto`. (p130-131)
- [ ] Every `text-transform: uppercase` rule has positive letter-spacing (~0.05em); no display/condensed face used for small text with widened tracking as a patch. (p133-134)
- [ ] Centered blocks are <= 3 lines and sibling centered blocks wrap to the same number of lines. (p129)
- [ ] Numeric table columns: figures AND their headers right-aligned; decimals line up. (p130)
- [ ] Link-dense lists/grids have no blanket link colour; inline links inside prose still have colour + underline. (p126-127)

Section F (colour):
- [ ] Grey text on white: lightness <= ~45% for text under 18px, <= ~55% for large text (L54% = 3.45:1, L42% = 5.41:1). Grep for light grey text tokens used at small sizes. (p162)
- [ ] No white text on mid-tone saturated pills/badges/buttons (typical results 1.6-3.1:1); measure every solid button's label contrast, do not assume the "500" shade passes. (p163)
- [ ] Secondary text on a coloured panel is neither near-white nor grey; it is visibly coloured and still >= 4.5:1 (hue rotated toward 60/180/300). (p165)
- [ ] For each colour scale in the tokens: S(lightest) and S(darkest) >= S(base); lighter shades' hue moves toward the nearest of 60/180/300 and darker toward the nearest of 0/120/240; total rotation <= 20-30 degrees. (p152-157)
- [ ] Dark yellows/oranges are not olive or khaki (hue held at ~50-60 while lightness drops = fail). (p156)
- [ ] Grey scale has one temperature: all greys share a hue (about +/-5 degrees) or all have S 0; saturation rises toward both ends; no mixing of warm and cool greys. (p159-160)
- [ ] Colour values are authored in HSL (or tokens derived from it), and values were not copied from an HSB picker. (p138-140)
- [ ] Palette has categorical accent colours if the UI colour-codes series/tags/events, separate from semantic red/yellow/green. (p147)
- [ ] Metric deltas / status pills carry an icon or sign, not only red/green. (p166-167)
- [ ] Chart series remain distinguishable in greyscale or a colour-blindness simulator; prefer one hue at 3 well-separated lightness steps over distinct hues. (p167-168)
- [ ] Two shades meant to look equally prominent are checked with perceived brightness `sqrt(0.299r^2+0.587g^2+0.114b^2)/255`, not HSL L. (p153)

# UI/UX audit: Ledgerly static fixture (index, invoices, signup)

**Screens reviewed:** `index.html` (public first screen, nav name "Launchpad"), `invoices.html` (invoice detail + list, nav name "The Vault"), `signup.html` (account creation), shared `styles.css`.   **Evidence:** code read (all 4 files in full) / scan.py / screenshots at 1280px and 400px for all 3 screens, all viewed / contrast.py on 19 color pairs. No live inspection, no keyboard run-through.
**Assumed top user tasks (inferred, nobody stated them):** 1) A newcomer works out what Ledgerly is and what it costs, then creates an account. 2) A signed-in user finds an invoice and sees whether it is paid or overdue. 3) The user acts on an invoice: send a reminder, mark it paid, download the PDF.

## Verdict
Beyond tweaking on all three screens: the problems are structural, not cosmetic. The biggest problem is that each top task is blocked or punished at its key moment: the only "create account" entry is a black, non-focusable `<span>`; the signup form demands card number, household income and date of birth behind placeholder-only fields with rigid formats; and "Mark as paid" is drawn as a disabled button at 1.68:1. There is no design system at all (0 tokens, 0 media queries, 14 font sizes, 18 spacing values, 22 colors), so every screen also looks unfinished and breaks at 400px. The strongest asset is the content underneath: the three feature bullets on index say exactly what the product does, and the invoice data model is complete and sensible.

## Top fixes
1. **Make the account-creation entry a real, primary link and delete the look-alikes** - task 1 currently has no visible, keyboard-reachable start: turn `.ghostlink` into `<a class="btn">Create your free account</a>` in the hero, make it the one solid button, demote or remove the other four CTAs, un-link-style `.fakelink`. Effort S. Resolves 1, 10, 11.
2. **Cut the signup form to what account creation needs (name, email, password), with real `<label for>` on each** - removes the sensitive-data demand and the unnamed controls in one pass; drop `pattern=`, the reset button, the permanent error, the instruction paragraph, "Cancel my subscription"; rename Submit to "Create account". Effort M. Resolves 2, 3, 22, 23, 24, 25, 26, 27, 38.
3. **Build an action pyramid on the invoice screen** - one solid primary ("Send reminder" while overdue), outline secondaries including a readable "Mark as paid", Delete as quiet red text placed apart. Effort S. Resolves 4, 17, 46.
4. **Fix contrast at the source: define a small palette and replace the failing pairs** - hero text, green/orange/grey buttons, promo accents, sidebar links, empty/footer text, `#999` borders. Dark-on-tint for colored buttons and badges. Effort M. Resolves 4, 6, 7, 12, 30.
5. **Rename the sections in plain words and make "you are here" visible** - Launchpad/The Vault/Hive/Pulse/Toolbox to Home/Invoices/... (owner must say what Hive, Pulse and Toolbox are); active item bold + dark with an accent underline, inactive soft grey; put the brand top-left as a link home; add an `<h1>` screen name that matches the nav word and the `<title>`. Effort S. Resolves 5, 8, 9, 15, 16.
6. **Rewrite the first screen top to answer "what is this / where do I start"** - h1 = what it is ("Send invoices and get paid faster"), 6-8 word tagline, move the three feature bullets up to replace the jargon paragraph, show price and the 3.5% fee in plain sight, move the 8 promos below or rotate one, delete "About this section" and "Which one are you?". Effort M. Resolves 10, 12, 13, 14, 28, 29.
7. **Introduce the missing systems while doing 4 to 6** - a type scale (about 6 sizes, px/rem, weights 400/700, body line-height 1.5), a spacing scale, one radius, one elevation pair lit from above, and at least one breakpoint so 400px is designed. Only the tokens actually used. Effort L. Resolves 18, 19, 20, 21, 31, 32, 34, 35, 46.

## System health
Enumerated from scan.py: font sizes **14** (13px x7, 14px x5, 0.875em x2, 12, 15, 16, 17, 22 x2 each, 11, 18, 1em, 2.5em, 21, 46px), weights **2** (700 x5, 300 x3), line-heights **1** (1.2), colors **22** (greys **15**), spacing values **18**, shadows **2**, radii **3** (0, 4px, 18px), border declarations **17**, tokens **0**, media queries **0**, declarations using `var()` **0** versus raw **199**.

What exists: a single shared stylesheet, a system font stack, one shared `.btn` base and one shared `.actions` row. Nothing else is systematic.
What is missing: type scale, spacing scale, palette, elevation scale, radius family, interaction states, breakpoints, tokens of any kind.
What to consolidate: sizes 11/12/13 to one small size, 14/15/16/17 to one body size, 21/22 to one heading size; greys `#999`/`#9a9a9a`/`#9b9b9b`/`#aaa`/`#bbb` to two or three steps of a single scale; spacing 6/7/8/9/10 to 8 and 12/13/14 to 12; both shadows to one "raised" value lit from above; radii to one; the four em sizes to px/rem. The 17 borders mostly go once spacing and fills separate regions.

## What's working
- Persistent section nav uses the same five names in the same order on all three screens (the names themselves fail, the consistency does not).
- `lang="en"` and a viewport meta tag are present on every page; the font is a neutral system stack with real 400 and 700 weights available.
- The "Archive" row action is correctly quiet: link-style `.quiet-danger` at 9.28:1, not a solid button repeated down the table (VR1.9).
- Section nav text contrast is good (7.46:1 and 8.45:1); default link blue on white passes (4.78:1); white on the hero blue passes (6.46:1); `.btn-blue` and `.btn-red` labels pass (4.78:1, 4.85:1).
- The three feature bullets on index are concrete, user-worded and task-focused: the best copy in the product, currently buried.
- Invoice table content is well chosen (number, client, issued, due, amount, status) and ISO dates sort and scan well; deliberate table density is acceptable.
